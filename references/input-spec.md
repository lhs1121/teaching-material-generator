# 输入字段规范与收集清单

本文件定义技能所需的「课程基本信息」字段，并给出对话式收集策略。生成三件套前，必须先收集齐**必填字段**；可选字段缺失时给合理默认，不阻塞流程。

---

## 字段定义

| 字段 | 标识 | 必填 | 说明 | 示例 |
|------|------|------|------|------|
| 专业大类 | `majorCategory` | ✅ | 职业教育专业目录中的大类 | 财经商贸大类 / 电子与信息大类 |
| 专业名称 | `majorName` | ✅ | 具体专业 | 商务数据分析 / 跨境电子商务 |
| 课程名称 | `courseName` | ✅ | 本课程名 | 商务数据分析实务 |
| 课程性质 | `courseType` | ⚠️ | 决定走哪条生成路径，见下方「步骤0 路由判断」 | 专业核心课 / 公共基础课 |
| 对应岗位（群） | `jobRole` | ⚠️ | 路径A必填；本任务服务的岗位 | 商务数据分析师 / 数据运营 |
| 典型工作任务 | `jobTask` | ⚠️ | 路径A必填；可由主题反推后确认 | 业务数据清洗与质量校验 |
| 授课章节/主题 | `topic` | ✅ | 本次要生成材料的章节或主题 | 数据清洗与预处理 |
| 授课对象 | `grade` | ✅ | 年级与层次 | 高职二年级 / 职业本科一年级 |
| 课时 | `hours` | ⚠️ | 本章节课时数（默认 2） | 2 / 4 |
| 授课地点 | `place` | ❌ | 教学场所 | 一体化实训室 / 智慧教室 |
| 授课教师 | `teacher` | ❌ | 教师名或"待填写" | 张老师 / （待填写） |
| 参考稿件 | `refDoc` | ❌ | 主编认可稿件路径，用于对齐结构与质量 | ./参考稿.docx |

## 步骤 0：路由判断（先于一切字段收集）

本技能支持两条生成路径，**必须先判定走哪条，再收集字段**：

| 路径 | 适用课程 | 教案结构 | 核心特征 |
|------|---------|---------|---------|
| **A 岗位驱动** | 专业核心课 / 实训课 / 理实一体课 | 十章 | 以典型工作任务为锚点，理论线与实践线并行，含「学情分析」「实践任务书」章 |
| **B 章节驱动** | 公共基础课 / 专业基础理论课 | 九章 | 以知识体系为锚点，v0.1.0 结构上新增学情分析 |

### 判断信号

| 信号 | 判定 |
|------|------|
| 用户明确给出岗位 / 岗位群 / 典型工作任务 | → A |
| 课程为专业核心课 / 实训课 / 理实一体课 | → A |
| 有对应职业技能等级证书（1+X）考核点或技能大赛赛项 | → A |
| 课程为公共基础课 / 专业基础理论课（经济基础、统计基础、思政、数学等） | → B |
| 授课地点为一体化实训室且连续排课 | → A 倾向 |
| 仅给出章/节/知识点，无其他信号 | 按 `courseType` 定：专业课→A，基础课→B |

### 反推机制（路径 A 的兜底，重要）

多数教师只给得出章节名，说不出典型工作任务。**此时不得直接退回 B**，应按 `PROMPT_TASK_INFER` 从主题反推典型工作任务，再用一句话请用户确认：

> 这节课按岗位任务来设计更合适。我把「{topic}」对应为典型工作任务「{jobTask}」（对应岗位 {jobRole}），按这个走吗？确认后按理实一体结构生成；若这节是纯理论课，我按标准教案出。

### 兜底提问

信号不足或相互冲突时，只问一次，不逐条追问：

> 这份材料按哪种方式生成？①**岗位驱动**（给出典型工作任务，出理实一体教案，含实践任务书，适合专业课）；②**章节驱动**（给出章节主题，出标准教案，适合基础课）。选①还是②？

判定后记录 `route: A | B`，后续所有模板按该路径选取，中途不切换。

## 对话式收集策略

### 第一步：识别意图
用户表达生成教案/课件/说课稿/备课意图，且提供了部分章节信息时，进入本技能。

### 第二步：补齐必填字段
用**一次简洁提问**补齐缺失的必填项，不要逐条追问。标准问法：

> 生成前确认 4 项关键信息：①专业大类 ②课程名称 ③授课章节 ④授课对象（年级/层次）。其余（课时、地点、教师、参考稿）可后补，先给默认。

### 第三步：确认生成范围
根据用户选择或默认，确定生成范围：
- 默认：**三件套一次出**（教案 + 配套课件大纲 + 说课稿）。
- 若用户明确只要其中一种，则只调对应模板。

### 第四步：参考稿件（可选）
若用户提供了参考稿件路径（`refDoc`），先读取其目录结构与表述风格，将关键结构摘录进 Prompt 的 `{refNote}`，保证对齐。无参考稿则跳过。

### 第五步：执行生成
按 `prompts.md` 选择模板 → 注入 `{input}` 与通用前置约束 → 输出三份 `.md`。

## 收集示例

### 示例一：路径 A（岗位驱动）

**用户**：帮我校商务数据分析的"数据清洗"那章做个教案和课件，高职大二，4 学时。

**步骤 0 路由**：
- 信号：商务数据分析属专业核心课、4 学时连续排课 → 判定 **路径 A 岗位驱动**。
- 用户只给了章节名，未给典型工作任务 → 触发**反推**。

**反推确认（一次提问，含补齐项）**：
> 这节课按岗位任务来设计更合适。我把「数据清洗与预处理」对应为典型工作任务「业务数据清洗与质量校验」（对应岗位 商务数据分析师 / 数据运营），按这个走吗？另还差 1 项：专业大类是什么？（如 财经商贸大类）

**用户**：按这个走，财经商贸大类。

**执行**：`route: A`，填齐 `{input}`（含 `jobRole` / `jobTask`），调路径 A 三套模板，生成：
- `业务数据清洗与质量校验 教案 V1.md`（十章 · 理实一体）
- `业务数据清洗与质量校验 课件大纲 V1.md`
- `业务数据清洗与质量校验 说课稿 V1.md`

### 示例二：路径 B（章节驱动）

**用户**：给我出一份"供求均衡理论"的教案，高职大一，2 学时，经济学基础课。

**步骤 0 路由**：
- 信号：经济学基础属专业基础理论课 → 判定 **路径 B 章节驱动**。**不反推**，不给实践任务书。

**补齐提问**：
> 还差 1 项：专业大类是什么？（如 财经商贸大类）其余按默认：地点"智慧教室"、教师"（待填写）"、无参考稿。确认后直接出三件套。

**执行**：`route: B`，调路径 B 三套模板（v0.1.0 原结构），生成：
- `供求均衡理论 教案 V1.md`（九章）
- `供求均衡理论 课件大纲 V1.md`
- `供求均衡理论 说课稿 V1.md`
